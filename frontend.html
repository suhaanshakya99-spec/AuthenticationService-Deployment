Quickstart

Four calls take you from nothing to a verified end user with a working session. Everything here is plain REST — fetch, curl, or whatever your stack already uses.

1

Create your developer account

This identifies you, not your end users. You'll use its access token to manage projects.

POST /developers/registration
{ "email": "you@company.com", "plain_password": "..." }
→ { access_token, refresh_token, token_type }
2

Create a project

Each project gets its own API key. That key is what your end users authenticate against — one per app or environment.

POST /developers/projects/new_project
Authorization: Bearer <developer access_token>
{ "project_name": "my-saas" }
→ { project_id, developer_id, API }
3

Register an end user

Now switch credentials: this call carries the project's API key, not your developer token.

POST /end-user/new-user
API-key: <project api key>
{ "email": "jane@example.com", "name": "Jane", "plain_password": "..." }
→ { access_token, refresh_token, token_type }
4

Call anything else as that user

Attach the end user's access token as a Bearer header, alongside the same API key.

POST /end-user/verification?token=<from your inbox>
API-key: <project api key>
Authorization: Bearer <end user access_token>

Keys & tokens

Three different credentials show up across this API. Mixing them up is the most common integration bug.

CredentialIdentifiesSent asLifetime
API keya projectAPI-key headeruntil you rotate it
access_tokena signed-in developer or end userAuthorization: Bearershort — re-issue via refresh
refresh_tokenthe same session, longer-livedrequest body / querylonger — used to mint new access tokens
Developer calls never take an API-key header — your own login gives you a Bearer token directly. End-user calls always need both: the project's API-key to say which app, and the user's Bearer token to say which person.

The JS client

A small wrapper that stores both tokens, attaches the right headers automatically, and re-issues an access token the moment one expires — so the rest of your app just calls auth.request(path). This is the same logic the dashboard and the console below run on.

class Keyforge {
  constructor(baseUrl, apiKey = null) {
    this.base = baseUrl.replace(/\/$/, "");
    this.apiKey = apiKey;
    this.access = localStorage.getItem("kf_access");
    this.refresh = localStorage.getItem("kf_refresh");
  }

  // low-level call: attaches API key + bearer token, retries once after refresh
  async request(path, { method = "GET", body, form, headers = {} } = {}, _retried = false) {
    const h = { ...headers };
    if (this.apiKey) h["API-key"] = this.apiKey;
    if (this.access) h["Authorization"] = `Bearer ${this.access}`;

    let fetchBody = undefined;
    if (form) { h["Content-Type"] = "application/x-www-form-urlencoded"; fetchBody = new URLSearchParams(form).toString(); }
    else if (body) { h["Content-Type"] = "application/json"; fetchBody = JSON.stringify(body); }

    const res = await fetch(this.base + path, { method, headers: h, body: fetchBody });

    // access token expired — refresh once, then retry the original call
    if (res.status === 401 && this.refresh && !_retried) {
      const refreshed = await this.refreshAccessToken();
      if (refreshed) return this.request(path, { method, body, form, headers }, true);
    }
    return res;
  }

  setTokens({ access_token, refresh_token }) {
    this.access = access_token; this.refresh = refresh_token;
    localStorage.setItem("kf_access", access_token);
    localStorage.setItem("kf_refresh", refresh_token);
  }

  // developers refresh via a bare ?token=, end users need the project's api_key too
  async refreshAccessToken() {
    const url = this.apiKey
      ? `${this.base}/end-user/refresh-token?api_key=${encodeURIComponent(this.apiKey)}&refresh_token=${encodeURIComponent(this.refresh)}`
      : `${this.base}/developers/verfiy-refresh_token?token=${encodeURIComponent(this.refresh)}`;
    const res = await fetch(url, { method: "POST" });
    if (!res.ok) return false;
    this.access = await res.json();
    localStorage.setItem("kf_access", this.access);
    return true;
  }

  registerUser(data) { return this.request("/end-user/new-user", { method: "POST", body: data }).then(r => r.json()).then(t => (this.setTokens(t), t)); }
  loginUser(username, password) { return this.request("/end-user/login", { method: "POST", form: { username, password } }).then(r => r.json()).then(t => (this.setTokens(t), t)); }
}
Storing tokens in localStorage is the simplest option and fine to start with — move to an httpOnly cookie set by your own backend if you later need protection from XSS reading the token.

Developer account

Manage your own login. No API-key header on any of these — your Bearer token is enough.

POST/developers/registration create a developer account
BODY (json)
{ "email": "you@company.com", "plain_password": "..." }
RESPONSE
{ "access_token": "...", "refresh_token": "...", "token_type": "bearer" }

Also sends a verification email in the background — the link's token is confirmed via /developers/verify-developer below.

POST/developers/dev-login exchange credentials for tokens
BODY (form-urlencoded — this one, not json)
username=you@company.com&password=...
RESPONSE
{ "access_token": "...", "refresh_token": "...", "token_type": "bearer" }
POST/developers/verify-developer?token=... confirm the emailed verification token
Authorization: Bearer
RESPONSE
{ "message": "Verification done" }
POST/developers/verfiy-refresh_token?token=... mint a new access token

No header needed — the refresh token itself is the credential. Response is the bare token string, not wrapped in an object.

RESPONSE

DELETE/developers/delete delete your account and every project under it
Authorization: Bearer
Cascades. Deleting a developer deletes their projects, which deletes those projects' end users.

Projects

Each project is an isolated pool of end users with its own API key. All of these need your developer Bearer token. The dashboard's Projects panel is a UI over exactly these five calls.

POST/developers/projects/new_project create a project, get its API key
Authorization: Bearer
BODY
{ "project_name": "my-saas" }
GET/developers/projects/all list your projects
Authorization: Bearer
PUT/developers/projects/update?project_id=... rename a project
Authorization: Bearer
BODY
{ "new_name": "my-saas-v2" }
DELETE/developers/projects/delete?project_id=... delete a project and its end users
Authorization: Bearer
GET/developers/projects/users?project_id=... list a project's end users
Authorization: Bearer
